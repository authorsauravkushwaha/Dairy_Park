# Security notes — Dairy Park website

This is a **static marketing website**: no server code, no database, no user
accounts, no forms, no payments and no ordering. That removes most of the usual
attack surface. The remaining risks are handled as follows.

## What is in place

- **HTTPS only.** GitHub Pages serves the site over HTTPS with a managed
  certificate, and the Content-Security-Policy upgrades insecure requests.
- **Strict Content-Security-Policy** (in every page `<head>`):
  `default-src 'self'`, `script-src 'self'` plus a SHA-256 hash for the inline
  JSON-LD block (generated by the build), `object-src 'none'`,
  `form-action 'self'`, `base-uri 'self'`. Only Google Maps may be framed and
  only Google Analytics may be contacted (and only if the owner configures it).
- **No inline scripts or event handlers** — `npm run check` fails the build if
  any `onclick=`-style handler or `<style>`/`style=""` appears.
- **No secrets.** No API keys, tokens or passwords exist in the repository. The
  Google Map is an `output=embed` URL that needs no key.
- **No third-party JavaScript by default.** The only optional remote script is
  Google Analytics, loaded after explicit consent.
- **XSS-safe rendering.** Owner content is inserted with `textContent` /
  `createElement`, never `innerHTML`, so text from `content.js` cannot inject
  markup. `innerHTML` is used only for hard-coded SVG icon paths in the script.
- **No form input to validate.** Contact happens through `tel:` links, so there
  is nothing to sanitise, spam-filter or submit. If a contact form is ever
  added, it must be handled by a validated server endpoint plus CSRF protection
  and spam control — do not bolt one on client-side only.
- **Privacy:** analytics is opt-in via a consent banner; declining loads
  nothing. See `privacy.html`.
- **Supply chain:** the build uses two pinned dev dependencies (`esbuild`,
  `jsdom`); `package-lock.json` is committed; Dependabot watches npm and the
  GitHub Actions used by the workflow. Deploys only publish the generated
  `dist/` artifact.

## Limits worth knowing

No website is impossible to attack. GitHub Pages cannot set custom HTTP response
headers, so the CSP ships as a `<meta>` tag; `frame-ancestors` from a meta tag is
ignored by browsers (clickjacking protection therefore relies on GitHub's own
headers). If the site later moves to a host that allows headers (Cloudflare
Pages, Netlify, Vercel), move the CSP into the response header and add
`X-Content-Type-Options: nosniff`, `Referrer-Policy` and
`Strict-Transport-Security`.
